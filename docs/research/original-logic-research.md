# スパイシリンダー系・開錠パズル 調査／独自再構成レポート

**作成日:** 2026年8月31日  
**目的:** カメレオンJPの実験場へ掲載する、3問合計の解錠タイムを競うブラウザゲームの基礎仕様を作る  
**調査の中心:** 『ラチェット＆クランク』（2002年）のスパイシリンダー系パズルと、『ラチェット＆クランク THE GAME』（2016年）のシリンダーロック

---

## 1. 結論

再現すべき核は、見た目の「金属製の丸い装置」ではありません。核になるのは、次の数学的な仕組みです。

複数の回転層に、光を出す部品と光を遮る部品が固定されています。プレイヤーが一つの層を回すと、その層に付いた部品がまとめて移動します。光は発射点から中心へ進み、中心を通って反対側の外周へ抜けます。途中に部品があれば止まり、必要な外周の受信点をすべて満たすと解錠します。

重要なのは、**すべての光を成功させる必要はなく、必要な受信点をすべて満たせばよい**ことです。余った光が受信点を外して赤く残っていても、必要な受信点がすべて点灯していれば成立します。この「完全一致ではなく、必要地点の網羅」という条件は、2002年版の攻略資料と2016年版の公式説明・完成画面の両方に整合します。

2002年版は、3層を回すだけの、時間制限のない思考型です。2016年版は、層の数が増え、層ごとに発射を止める操作が加わります。元作品の問題は手作業で配置された固定問題であり、ランダム生成や3問タイムアタックは元作品にはない、本作独自の競技部分になります。

したがって、ブラウザゲームでは、次の方針が最も安全で実用的です。

1. 光路、回転層、遮断、受信点の網羅という抽象ルールだけを独自コードで実装する。
2. 元作品の名称、画像、音、画面構成、部品形状、文章、問題配置は使わない。
3. 12方向の金属製円盤ではなく、16方向の色素膜や多角形層など、別の世界観と画面表現にする。
4. 正解状態から独自問題を逆生成し、解法探索で「必ず解けること」と難しさを検査する。
5. 競技では全員に同じ3問を出し、問題の識別番号と生成版をランキングに保存する。

この方針なら、元の遊びの核を保ちつつ、見た目、問題、競技ルール、実装を独自の作品として組み立てられます。ただし、権利侵害が絶対にないと保証するものではありません。公開前には、名称・ロゴの商標調査と、完成画面が元作品へ近づきすぎていないかの確認が必要です。

## 2. 調査結果の確度

本レポートでは、情報を次のように分けます。

| 表記 | 意味 |
|---|---|
| **確認済み** | 公式説明、ゲーム内説明の記録、複数の完成画面などで直接確かめられた内容 |
| **有力な推定** | 複数資料と画面上の挙動が一致しているが、内部コードや公式設計書では確認できない内容 |
| **未確認** | 資料だけでは決められず、実機動画を一コマずつ確認する必要がある内容 |
| **本作への提案** | 元作品の事実ではなく、ブラウザゲームにするための独自仕様 |

元作品の内部コードや公式のパズル設計書は確認できませんでした。そのため、光が部品へ当たった瞬間の細かな優先順位などは、画面と攻略資料から再構成しています。実装時には一部を切り替え可能な設定にしておくのが安全です。

## 3. シリーズ内での位置づけ

シリーズには、作品ごとに異なる開錠・侵入用の小ゲームがあります。ただし、今回の「回転層と光路」を直接引き継ぐ系統は、主に2002年版と2016年版です。

| 系統 | 主な操作 | 今回との関係 |
|---|---|---|
| 2002年版のスパイシリンダー系 | 3つの層を回し、光を外周へ通す | 基本ロジックの原型 |
| 2016年版のシリンダーロック | 層を回し、必要に応じて層の発射を止める | 発展形。競技向けの中心候補 |
| エレクトライザー系 | 回路の接続部品を反転して電気を通す | 別ルール |
| インフィルトレーター系 | 球面上の経路を時間内につなぐ | 別ルール。時間圧力の参考にはなる |
| ハッカー系 | 管内を進む対象を選別・迎撃する | 反応型で、今回とは別物 |
| デクリプター系 | 傾き操作で球を導く | 物理操作型で、今回とは別物 |
| 『Rift Apart』のGlitch | 小型ロボットでウイルスを撃つ | 行動型で、今回とは別物 |

このため、本作へ別系統の操作を混ぜる必要はありません。3問の中でルールが変わると、純粋な解錠タイムを比べにくくなります。難度は、層数、遮断関係、発射停止の必要性、最短操作数で上げるべきです。

## 4. 2002年版のロジック

### 4.1 確認できた基本構造

2002年版では、外側・中央・内側の3層があります。上下入力で動かす層を選び、左右入力で選択中の層を回します。各層には、光の発射器と遮断部品が固定されています。一つの層を回すと、その層に付いたすべての部品が同じ角度だけ移動します。

外周には点灯させる必要がある受信点があります。必要な受信点は、未達成時に赤、光が届くと緑になります。必要な受信点がすべて緑になると解錠します。時間制限はありません。

攻略資料では盤面を時計の時刻で記録しており、1時、2時……12時という離散的な位置で表しています。このため、2002年版は**12方向の固定位置を一段ずつ回す構造**と考えるのが妥当です。

### 4.2 発射器、遮断部品、受信点

2002年版には少なくとも次の3種類があります。

- 光を出す発射器
- 光を止める遮断部品
- 外周にある、満たすべき受信点

光は、発射器から中心側へ進み、中心を越えて反対側の外周へ向かいます。途中に遮断部品や発射器本体があれば、そこで止まると考えると、記録された完成配置と画面に整合します。一方、光どうしが中心で交差しても、互いを止めません。

一例として、4時方向に発射器がある場合、その光は中心を通って10時方向へ向かいます。4時から中心まで、または中心から10時までの途中に部品があれば光は止まります。

### 4.3 成功条件は「必要地点の網羅」

ここは実装で間違えやすい部分です。

成功条件は「すべての発射器が緑になること」ではありません。必要な外周の受信点がすべて緑になることです。攻略資料には、発射器の数が受信点より多く、余った光が赤いままでも解ける盤面があると明記されています。

したがって、次の判定は誤りです。

```text
点灯した方向 == 必要な方向
```

正しくは次です。

```text
必要な方向が、点灯した方向の中にすべて含まれる
```

### 4.4 問題数と固定性

確認した攻略資料では、2002年版の解錠盤面は合計14件です。各場所に決まった初期状態と完成配置があり、毎回ランダムに生成される構造ではありません。また、一つの盤面に複数の解き方があり得るとされています。

本作では、この14件の配置や解答手順を転用しません。使用するのは抽象化したルールだけです。

## 5. 2016年版で追加・変更された要素

### 5.1 公式に確認できる目的

2016年版の公式オンライン説明では、スパイシリンダーを使い、「パズルのすべてのポートにレーザーを当てると開く」と説明されています。攻略資料では全16件が確認され、ゲームの難易度設定によって正解配置が変わるとされています。

つまり、2016年版も固定された場所ごとの問題ですが、少なくとも難易度別に別配置が用意されています。

### 5.2 層数の増加

序盤には少ない層の簡単な問題があり、後半には4層の問題が登場します。難しさは、単に層が増えるだけではありません。一つの層に複数の発射器があり、それらがまとめて回るため、一つの受信点を合わせると別の光が遮られる関係が増えます。

### 5.3 層ごとの発射停止

2016年版では、選択中の層の発射をオン・オフできます。攻略記録には、外側の層をオフにし、中央と内側だけをオンにする完成例があります。すべての層をオンにする問題もあります。

この操作は、単なる光の本数調整ではありません。余分な発射器が別の光路を邪魔する配置では、層を止めること自体が解答になります。

### 5.4 余った赤い光を許す

完成画面の中には、必要な外周ポートがすべて緑になっている一方で、外周の受信点を外した赤い光が残っている例があります。これは2002年版と同じく、成功条件が「すべての必要地点を満たすこと」であり、「すべての光が正解であること」ではないと判断できます。

### 5.5 遮断の扱い

攻略資料では、他の層を止め、一番外側から一層ずつ置き直し、光を遮らない位置を探す方法が勧められています。したがって、層上の部品が他の光を遮ることは有力です。

ただし、次の細部は公式資料だけでは確定できません。

- 発射を止めた層の部品が、物体として光を遮り続けるか
- 発射器本体と専用の遮断部品が内部的に別種類か
- 同じ方向へ複数部品が重なる特殊状態の優先順位

ブラウザ版では、まず「停止中の発射器も物体としては残り、他の光を遮る」を採用候補にします。ただし、実機動画との比較で切り替えられる設定にしておきます。

## 6. 2002年版と2016年版の比較

| 観点 | 2002年版 | 2016年版 | 本作の推奨仕様 |
|---|---|---|---|
| 回転位置 | 12方向 | 12方向とみられる | 16方向へ変更 |
| 層数 | 常に3層 | 段階的に増え、4層もある | 3層、4層、4層の3問 |
| 層の発射停止 | なし | あり | 第2問から導入 |
| 遮断部品 | 明確に存在 | 層上の部品が光路を遮る | 独自形状の遮断片を明示 |
| 光どうしの交差 | 妨げない | 妨げないと考えられる | 妨げない |
| 成功条件 | 必要な受信点をすべて点灯 | すべてのポートを点灯 | 必要地点の網羅 |
| 余った光 | 赤いままでも可 | 赤いままでも可 | 可 |
| 問題 | 固定14件 | 固定16件、難易度差あり | 独自の決定的ランダム生成 |
| 時間競争 | なし | 元の解錠は思考型 | 3問の合計時間を競う |
| 自動解錠 | 確認対象外 | あり | 練習のみヒント、競技はなし |

「決定的ランダム生成」とは、同じ識別番号からは必ず同じ問題を作れる方式です。見た目はランダムでも、競技参加者へ同じ3問を配れます。

## 7. ブラウザ版へ移せる数学的ルール

### 7.1 盤面のデータ

盤面は、次の情報だけで表せます。

- 外周を何方向に分けるか
- 必要な受信点の位置
- 各層に付く発射器の相対位置
- 各層に付く遮断片の相対位置
- 各層の現在の回転量
- 各層の発射がオンかオフか

本作では、元作品の12方向を避け、**16方向**を推奨します。16方向ならスマートフォンでも位置の違いを見分けやすく、32ビット整数一つで点灯状態を扱えます。

### 7.2 位置の計算

方向の総数を `S`、層の回転量を `rotation`、層に固定された部品の位置を `localSlot` とします。

```text
実際の位置 = (localSlot + rotation) mod S
```

一つの層を1段回すと、その層に付いたすべての発射器と遮断片へ同じ回転量が加わります。

### 7.3 光の進み方

外側から内側へ層を `0, 1, 2...` と数えます。発射器が方向 `a` にあるとします。

1. 発射器から中心へ、方向 `a` の線上を進む。
2. 発射器より内側の層に部品があれば、そこで止まる。
3. 中心を通過した後、反対方向へ進む。
4. 反対方向は `(a + S / 2) mod S` で求める。
5. 反対側の線上に部品があれば、そこで止まる。
6. 止まらず外周へ届けば、その方向を点灯済みにする。

光どうしが中心で交差しても止まりません。

### 7.4 成功判定

必要な受信点を `targetMask`、実際に点灯した方向を `litMask` とします。

```text
(litMask & targetMask) === targetMask
```

これで、必要な地点をすべて満たしているかを判定できます。余った光が別方向へ届いても、失敗にはしません。

### 7.5 中核処理の疑似コード

```text
点灯集合を空にする

オンになっている各層について:
  その層の各発射器について:
    発射器の実際の方向を求める

    発射器から中心までの線上を調べる
    部品に当たったら、この光は失敗

    中心を越えた反対側の線上を調べる
    部品に当たったら、この光は失敗

    外周まで届いたら、反対方向を点灯集合へ加える

必要な受信点がすべて点灯集合に含まれていれば解錠
```

### 7.6 実装で切り替え可能にする項目

元作品の細部が未確認のため、次は設定値にします。

```text
inactiveEmittersBlock: true / false
crossingBeamsBlock: false
winMode: coverage
slotCount: 16
```

`inactiveEmittersBlock` は、発射を止めた部品が他の光を遮るかを表します。最初は `true` を候補にし、実機映像と合わなければ変更します。

## 8. 独自問題をランダム生成する方法

### 8.1 完全な乱数配置ではいけない理由

部品を無作為に置くだけでは、解けない問題、最初から解けている問題、1回動かすだけの問題、どの層を動かしても同じ問題が大量にできます。ランキング用の問題として使えません。

そこで、**先に正解状態を作り、そこから開始状態を離す**方法を使います。

### 8.2 逆向き生成の流れ

1. 方向数、層数、発射器数、遮断片数を決める。
2. 各層の部品を、重なりや強すぎる対称性を避けて配置する。
3. 隠れた正解状態として、各層の回転量と発射のオン・オフを決める。
4. その状態で光を計算し、外周へ届く方向を求める。
5. 届いた方向の一部を、必要な受信点として採用する。
6. 正解状態から複数回の合法操作を行い、開始状態を作る。
7. 解法探索で、本当に解けるか、最短何手かを計算する。
8. 難度条件を外れた問題は捨て、作り直す。

この方法なら、少なくとも一つの正解がある状態から作るため、解けない問題を大幅に減らせます。ただし、別の近道が生まれる可能性があるので、最後の解法探索は必須です。

### 8.3 問題を捨てる条件

次のどれかに当たる問題は採用しません。

- 開始時点ですでに解けている
- 最短操作数が想定範囲より短い、または長い
- 一つの層が解答へまったく影響しない
- 中級以上なのに遮断関係が一度も使われない
- 発射停止を導入した問題なのに、停止操作が不要
- 同じ形が等間隔に並び、回す前から答えが見えすぎる
- 最短解が多すぎて、ほぼ何をしても解ける
- 部品と受信点が重なって見え、画面上で判断できない
- 前の問題と形が似すぎている

### 8.4 同じ問題を再現する識別番号

問題生成には、乱数の元になる文字列を使います。これを「シード」と呼びます。

```text
daily-2026-09-01-set-A
```

同じシードと同じ生成版を使えば、いつでも同じ3問を作れます。ランキングには次を保存します。

```text
runId
seed
puzzleGeneratorVersion
engineRuleVersion
playerName
totalTimeMs
puzzleTimesMs
moveCount
inputReplay
```

生成方法を後から直した場合は、生成版を変えます。版が違う記録を同じランキングで比べてはいけません。

## 9. 解法探索と難度の測り方

### 9.1 近い状態から順番に調べる

開始状態から、1手で行ける状態、2手で行ける状態、3手で行ける状態という順に調べます。この方法を**幅優先探索（Breadth-First Search）**と呼びます。

一つの手は、次のいずれかです。

- 一つの層を左へ1段回す
- 一つの層を右へ1段回す
- 許可された層の発射をオン・オフする

現在選択中の層は、盤面の答えに影響しないため、探索状態へ含めません。

### 9.2 状態数

16方向、4層、各層にオン・オフがある場合、最大状態数は次です。

```text
16 × 16 × 16 × 16 × 2 × 2 × 2 × 2
= 1,048,576状態
```

100万程度なら工夫すれば処理できますが、競技開始後にiPhoneで毎回すべて探索する必要はありません。問題は事前生成するか、開始前に別処理へ回します。ゲーム中は光路の再計算だけにします。

### 9.3 難しさを決める指標

層数だけでは難度を測れません。本作では次を組み合わせます。

- 最短操作数
- 最短解が何通りあるか
- 発射停止が必須か
- 遮断を避ける配置が何回必要か
- 一つの操作で点灯状態が大きく変わる度合い
- 正解に見えるが最後の一つだけ届かない配置の数

最短操作数が同じでも、答えが一通りしかない問題と、十通りある問題では体感が違います。

## 10. 3問タイムアタックの推奨仕様

### 10.1 競技の基本形

名前を入力して開始ボタンを押すと、3秒のカウントダウンを表示します。3問はカウントダウン前にすべて生成・描画準備しておきます。「スタート」の瞬間から第1問の計測を始めます。

3問を解くと、各問題の時間と合計時間を表示します。順位は同じ問題セット、同じルール版だけで比べます。

### 10.2 問題構成

| 問題 | 推奨内容 | 目標最短操作数 |
|---|---|---:|
| 第1問 | 3層。回転と受信点の網羅だけを理解させる | 4～7手 |
| 第2問 | 4層。発射停止を1回以上使う | 7～11手 |
| 第3問 | 4層。複数の遮断関係と発射停止を組み合わせる | 10～16手 |

これは初期案です。実際のプレイ記録を集め、中央値と離脱率を見ながら調整します。

### 10.3 計測方法

端末性能で差が出ないよう、問題切り替えの演出時間は合計タイムへ含めません。各問題で操作可能になった瞬間から解錠判定までを測り、3問分を足します。

順位は次の順で決める案が適切です。

1. 3問の合計時間が短い
2. 同じ時間なら総操作数が少ない
3. それも同じなら先に有効記録を送信した人

やり直しボタンは使えてよいですが、その問題の時間は進み続けます。誤操作はすでに時間として不利になるため、別の秒数罰を重ねる必要はありません。

### 10.4 ランダムと公平性

参加者ごとに別の3問を出し、その合計時間を同じランキングで比べるのは公平ではありません。競技では、次のどちらかにします。

- 日替わりで全員が同じ3問を解く
- 一定期間ごとの大会セットとして、全員が同じ3問を解く

練習では毎回別問題を出して構いません。競技と練習を分けることが重要です。

### 10.5 ヒントと自動解答

競技ではヒント、自動解答、最適手の表示を使えなくします。練習では、次の段階式ヒントが使えます。

1. 今の状態で遮られている光を強調する
2. 正解に必要な層を一つ知らせる
3. 次の一手を知らせる
4. 全手順を再生する

練習でヒントを使った記録はランキングへ送らないようにします。

## 11. 不正なスコアを防ぐための記録方法

ブラウザだけで計算した合計時間をそのまま送ると、開発者ツールや通信書き換えで好きな値を送れます。正式ランキングでは、サーバー側で記録を再現できる形が必要です。

### 11.1 推奨手順

1. 開始時、サーバーが問題シード、開始時刻、使い捨て識別子を発行する。
2. ブラウザは「どの層へ、何を、開始から何ミリ秒後に行ったか」を記録する。
3. 終了時、3問分の操作記録を送る。
4. サーバーが同じ問題を再生成し、操作を最初から再生する。
5. 各問題が本当に解けたか、操作順、所要時間、問題版が正しいかを確かめる。
6. 検査に通った記録だけランキングへ入れる。

画面を別のアプリへ切り替えた間も、正式記録の時間は進み続ける仕様が自然です。表示用には端末の高精度時計を使い、最終判定はサーバーの開始・終了時刻と操作記録で検査します。

サーバー検査をまだ用意しない初期版では、「端末内ベスト」または「未検証記録」と明記し、正式ランキングと呼ばない方が安全です。

## 12. iPhone向けの操作と画面

円形の盤面は縦画面と相性がよいため、1画面内へ次の順で配置します。

```text
問題 1/3　合計時間　現在の問題時間

        盤面

層1　層2　層3　層4
左回転　発射オン/オフ　右回転
やり直す
```

層そのものをタップして選べるようにしつつ、下部にも大きな層選択ボタンを置きます。精密なドラッグだけを正式操作にすると、画面サイズ、指の移動量、ブラウザの挙動で差が出ます。競技の基本操作は大きな左右ボタンにし、スワイプ回転は練習用の補助にするのが公平です。

描画は、拡大しても線がぼけにくい**SVG**を推奨します。円、線、部品、受信点を別要素として描けるため、色だけでなく形や模様も変えられます。

赤と緑だけで状態を区別してはいけません。未達成は空洞と点線、達成は塗りつぶしと発光など、形も変えます。発射停止中の層は、暗くするだけでなく、停止記号を重ねます。

回転演出は見た目だけにし、入力した瞬間に内部状態を確定します。60ヘルツと120ヘルツの端末で、同じ入力が同じ時刻・同じ結果になる必要があります。

## 13. 権利を避けるための独自化

### 13.1 利用しやすい部分と、避ける部分

文化庁の説明では、単なる事実、データ、アイデア、ありふれた表現は著作物に当たらない場合があります。一方で、具体的な画像、文章、音、動き、プログラム、キャラクター、画面の組み合わせは保護され得ます。また、著作権だけでなく、商標、意匠、不正競争防止法なども別に確認する必要があります。

このため、抽象化した「回転層を動かし、遮断を避け、必要な外周地点をすべて満たす」というルールを独自コードで作ることは、元画面を写すことより危険が低いと考えられます。ただし、同じルールなら何をしてもよいという保証ではありません。

### 13.2 使用しないもの

公開版では次を使いません。

- シリーズ名、作品名、スパイシリンダー、Trespasser、ガラメカなどの固有名称
- キャラクター、惑星、会社、装置の固有名
- ロゴ、画像、スクリーンショット、動画の切り抜き
- 元作品の効果音、音楽、開錠演出
- チュートリアル文章や説明文の言い換えに近い転用
- 金属製の同心円装置、緑の外周ポート、矢印付き発射器などを同じ組み合わせで描くこと
- 2002年版14件、2016年版16件の問題配置と解答手順
- 「○○風」「○○の再現」「○○クローン」といった公開上の宣伝

### 13.3 推奨する独自世界観

カメレオンJPに合わせ、機械の鍵ではなく、**色素細胞の信号経路を整える実験**へ置き換える案が適しています。

複数の不規則な色素膜が回転し、発信核から色の波が中心を通って外側の色素芽へ届きます。遮断片は、光を止める機械部品ではなく、色を吸収する暗い細胞です。すべての必要な色素芽が開くと、中央に独自の模様が咲きます。

見た目をさらに離すため、次を採用します。

- 円ではなく、角が丸い16角形または有機的に歪んだ層
- レーザーではなく、太さが脈動する色の流れ
- 赤・緑ではなく、藍・琥珀などを基本にし、形も変える
- 外周ポートではなく、葉、鱗、細胞のような受信部
- 金属音ではなく、水滴、膜、木琴に近い独自音
- 解錠ではなく「安定」「同期」「発色完了」などの独自表現

名称とロゴは公開前にJ-PlatPatで商標を調べます。完成画面は、元作品を知らない人が見て、同シリーズの公式作品や関連作品と誤解しない状態にします。

### 13.4 開発記録を残す

実装時には、次を文書へ残します。

- 参考にしたのは抽象ルールだけであること
- 元作品のコード、画像、音、問題データを取得・転用していないこと
- 独自の方向数、生成方法、世界観、部品形状を選んだ理由
- 問題がすべて独自シードから生成されたこと
- 公開前に名称と画面を確認した記録

これは権利非侵害を保証するものではありませんが、独立して設計した経緯を明確にできます。

## 14. 推奨する初期仕様

### 14.1 ルール

- 外周は16方向
- 第1問は3層、第2・第3問は4層
- 一層につき発射器1～3個、遮断片0～2個
- 光は中心を通って反対側へ進む
- 光どうしは遮らない
- 部品に当たると止まる
- 必要な受信点をすべて満たすと成功
- 余った光が外れていてもよい
- 第2問以降は層の発射停止を使う
- 停止中の発射器が遮断物になるかは設定化し、初期候補は「なる」

### 14.2 競技

- 名前入力必須
- 3秒カウントダウン
- 同一シードの3問
- 3問の操作可能時間だけを合計
- 同時間は操作数で比較
- 競技中のヒントなし
- 問題切り替え前に次の問題を描画済みにする
- 同じ生成版だけを同じランキングで比較
- 上位10件を表示

### 14.3 技術構成

盤面計算は、画面描画から分離した一つの純粋な処理にします。純粋な処理とは、同じ盤面と同じ操作を渡せば、端末や描画速度に関係なく必ず同じ結果を返す処理です。

推奨構成は次です。

```text
PuzzleEngine
  盤面状態の更新
  光路計算
  成功判定
  操作記録の再生

PuzzleGenerator
  シードから問題を生成
  正解状態から開始状態を作成
  解法探索で検査

GameController
  3問の進行
  計測
  途中状態

Renderer
  SVG描画
  回転演出
  状態表示

ScoreService
  開始識別子の取得
  操作記録の送信
  ランキング取得
```

## 16. 必須の自動検査

### 16.1 ルール検査

- 一層を1段回すと、その層の全部品だけが1段動く
- 左右回転を同じ回数行うと元へ戻る
- オフの層は光を出さない
- 遮断片に当たった光は外周へ届かない
- 光どうしが中心で交差しても止まらない
- 反対側の方向計算が正しい
- 必要な受信点がすべて点灯すれば、余った赤い光があっても成功する
- 一つでも必要な受信点が消えていれば成功しない
- やり直しで完全に開始状態へ戻る

### 16.2 生成検査

- 同じシードと版から同じ問題が作られる
- 違うシードから十分に異なる問題が作られる
- 開始状態が成功状態ではない
- 解法探索で必ず正解が見つかる
- 最短操作数が難度範囲内にある
- 発射停止を必須にした問題では、最短解に停止操作が含まれる
- 使われない層がない
- 元作品の既知の固定配置を問題データとして持っていない

### 16.3 競技検査

- カウントダウン中は操作できない
- 「スタート」と同時に操作可能になる
- 問題切り替え時間が計測へ混ざらない
- 60ヘルツと120ヘルツで同じ操作記録の結果が一致する
- 画面を離れた時間を短縮に利用できない
- 操作記録の再生で3問すべての成功を再現できる
- 改ざんした時間、存在しない問題版、途中終了の記録を拒否する

### 16.4 画面検査

- iPhoneの縦画面でスクロールせず操作できる
- 部品、光、受信点が重ならず判別できる
- 色を見分けにくくても、形と模様で状態が分かる
- ボタンを連打しても入力が欠けたり二重になったりしない
- 長押しによる文字選択や画像保存がゲーム操作を邪魔しない
- 画面回転や再読み込みで競技記録が不正に継続しない

## 17. 未確認事項と、実装時の扱い

次は現時点で断定できません。

1. 2016年版で、発射を止めた発射器本体が他の光を遮り続けるか。
2. 2016年版で、専用遮断部品と発射器本体が内部的に別の種類か。
3. 盤面上で同じ方向へ複数部品が重なった場合の厳密な判定順。
4. 難易度変更が、部品配置、初期回転、必要ポート、層のオン・オフのどれを変えているか。
5. 地域版や移植版で、固定盤面の初期状態が同一か。

これらは、実装の前に複数のゲームプレイ動画を一コマずつ比較して追加検証します。ただし、本作は元作品の内部挙動を完全に複製する必要はありません。競技として一貫し、説明どおりに動き、独自の問題を正しく生成できることを優先します。

## 18. 最終判断

この企画は、ブラウザゲームとして十分に成立します。

特に相性がよい点は、盤面が小さく、入力が離散的で、端末性能に左右されにくいことです。解法探索で問題の正しさと難しさを自動検査できるため、手作業だけで大量の問題を作る必要もありません。3問の合計時間へ変えることで、元作品にはない「理解の速さ、先読み、操作の正確さ」を競うゲームになります。

開発方針は、**数学的な核は丁寧に再構成し、外見、用語、問題、競技、音、演出は独自にする**のが適切です。元画面を似せるほど完成度が上がるわけではありません。カメレオンJPの色素・膜・発色という題材へ置き換え、独自の16方向ルールと問題生成を持たせた方が、作品としても明確になります。

## 19. 調査の進め方と判断根拠

共有できる調査手順は次のとおりです。

まず、公式オンライン説明で2016年版の正式な成功条件を確認しました。次に、2002年版のゲーム内説明を記録した日本語資料と、当時の詳細な攻略資料を照合し、操作、3層、遮断部品、余った光を許す条件を確認しました。その後、2016年版の16件の攻略記録、層のオン・オフ説明、複数の完成画面を比較しました。

画面から推定した内容については、一つの画像だけで決めず、発射器と外周ポートが中心を挟んで反対側に並ぶ複数例を照合しました。公式資料に書かれていない細部は「未確認」とし、実装を切り替えられるようにしました。

権利面は、文化庁の著作権説明、経済産業省の不正競争防止法の概要、INPITのJ-PlatPat案内を基準に整理しました。これは一般的な調査であり、個別案件に対する法的判断ではありません。
