## レビューと修正

実装と並行した確認で、問題に発光紋が存在する条件と、旧形式・検査専用項目の混入を拒否する境界を修正しました。問題読込を検証してから開始する順序、失敗時の日本語表示、音設定の内部値も確認対象に含めています。

Sol Highの独立レビューでは次の4件を再現し、修正しました。指摘修正後の独立レビューはR1合格で、未解消の阻害問題はありません。

| 指摘 | 修正内容 |
|---|---|
| 大きすぎる時刻を受理し、その履歴の再生で拒否する | 入力時も安全に整数を扱える上限までとし、再生時とそろえる |
| 回転配列の欠けを見逃し、状態番号がNaNになる | 3要素を一つずつ確認し、欠けた配列と旧状態を拒否する |
| 初期成功問題に不正履歴を渡すと、返却状態と成功フラグが矛盾する | 初期状態を先に評価し、不正履歴の返却結果にも同じ判定を使う |
| 未知の追加値を深くたどり、循環・深い入れ子で例外になる | 既知の形式だけを検査し、未知の項目の中へ進まない |

このほか、不明な操作種別を不正な環と同じ理由で拒否していたため、`bad-type` と `bad-ring` を分けました。

必須検査と実際のassertを照合し、全状態で6操作の逆操作、余分な光と未点灯の必須受光紋、再生状態の一致、形式異常の個別拒否も追加しました。

正式版の `src/`（テストを除く）と `content/` を対象に、旧発光状態・切替回数・旧規則版・切替処理の参照がないことを検索で確認しました。旧 `prototype/`、履歴資料、旧形式の拒否テストはこの検索の対象外です。
