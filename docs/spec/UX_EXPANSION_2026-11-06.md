## 2. 現状、方式比較、維持する契約

現行は `src/input.ts` の共通受付、`src/app.ts`（1問確認）と `src/run-ui.ts`（5問）の左右ボタン、`src/board.ts` の300×300座標、`src/three-board.ts` のBoardView＋SVG操作面で構成される。`src/sound.ts` は6種類のWeb Audio合成音。`run-ui.ts` は成功時に両側の紙吹雪を出し、`src/run.ts` の `INTERMISSION_MS = 1_500` で次へ進む。BoardViewは更新ごとにSVG入力ノードを差し替えるため、そのノードをスワイプの継続所有者にしてはならない。

| 案 | 利点・欠点 | 採否 |
|---|---|---|
| 横スワイプで選択中の輪を左右へ回す | 判定は簡単。ただし円の上半分・下半分で指と回転の向きが一致しない | 不採用 |
| 触れた輪の円周方向をなぞり30度ごとに確定 | 石板を直接回す感覚。角度境界と入力の寿命管理が必要 | 採用 |
| 自由角度・慣性で回し、指離し時に判定 | 派手だが成功時刻・手数・離脱時の確定が変わる | 不採用 |

演出は独立したDOM/SVGの装飾層を採用する。50種類の3Dシーン追加は資源負荷と代替表示の差が大きいため採用しない。Web Audio合成を拡張し、外部音源・ライブラリは追加しない。

以下は全工程の固定条件。

- 12方向・可動輪3本・常時発光・回転のみ、90問・900組、成功判定、問題順序、保存形式を維持する。
- 1段階30度の受理につき1手。選択は0手。成功入力時刻で時計を止め、成功表示は1,500ms。描画・SEの完了を待たない。
- 初回カウントダウン3秒、説明・中断確認・背面時間を計測に含める既存規則を維持する。
- 音設定はホームのみ、初期ON、保存値を尊重する。動きを減らす設定を尊重する。
- Node 24.19.0 / npm 11.9.0、TypeScript 5.9.2、Three.js 0.180.0、既存Playwrightを使い、依存追加なし。
- `src/core/`・`content/`の規則・問題、ランキング、外部接続、本番公開は本追加の変更対象外。

優先関係: ユーザーの追加指定 → 本書のUX-SE/SW/SZ/FXに関する契約 → [既存計画2.1](../planning/IMPLEMENTATION_PLAN.md)と[現行仕様2.2](CURRENT_GAME_SPEC.md)。標準矢印ボタン、入力の1操作の定義、盤面寸法、SE6種、演出のみを本書で更新する。それ以外の品質条件・公開条件は緩めない。実装前の現状説明は旧仕様のまま区別して残す。

## 3. スワイプ回転

### 3.1 開始・確定

- Pointer Eventsを使用。タッチ、ペン、マウス左ドラッグを共通化する。輪の選択ボタンと盤面の単純タップは0手で残す。
- 座標はSVGの画面変換行列の逆行列で300×300へ戻す。中心(150,150)、輪の半径31〜55 / 61〜85 / 91〜115を使用し、隙間・中心・固定外周から開始しない。DPRを二重に掛けない。
- `pointerdown`時に触れた輪を固定して選択する。安定した `.board-host` にpointer captureを取り、差し替わるSVGパスには取らない。pointerIdとrun/question/input世代を保持する。
- 初期位置から8 CSS px未満は選択のみ。8px以上かつ累積角度が±30度に達した時点で1段階確定する。正角度は画面上の時計回り=`r`、負角度は反時計回り=`l`。1段階受理ごとに残角度から±30度を除く。例えば+65度で右2手・残5度、そこから−35度で左1手。
- ±180度境界は最短の符号付き角度差へ正規化する。1サンプルの角度差が90度を超える、非有限座標、中心半径20未満に入る場合は残りのジェスチャーをキャンセルする。既に受理した手は巻き戻さない。coalesced eventsは時刻順で処理し、同じ末尾サンプルを二重計算しない。
- 各段階を既存の `acceptRotation` と共通入力受付へ1件ずつ渡す。長いスワイプでも成功した段階で即終了し、残角度・後続サンプルを捨てる。pointerupは未確定残角度を捨てるだけで追加回転しない。慣性・長押しリピートなし。
- 自由角度へ論理盤面を動かすプレビューは作らない。部品と光路は同時に30度更新し、未確定の指の動きは装飾軌跡で示す。音・演出の乱数は問題抽選へ渡さない。

### 3.2 中断・競合

2本目の指、pointercancel、lostpointercapture、盤面外での指離し、blur、hidden、pagehide、resize/画面回転、説明・中断確認、練習やり直し、問題変更、終了、disposeで残入力を破棄・captureを解放する。複数指後は全指が離れるまで再開しない。指が隣の輪を横切っても操作対象は変えない。

スワイプ後の互換clickで再選択・再回転しない。抑制対象は当該pointer系列に限り、補助技術のclickや次の別入力を時間窓で一括禁止しない。キーボードや補助ボタンで選択・回転する場合は先に進行中ジェスチャーを中止する。古いSVGノード・古いrun/question世代のイベントは拒否する。SVG差替・同一問の通常回転ではinput世代を進めない。run開始、問題変更、リセット、中断境界で世代を進め、再開には新しいpointerdownを要求する。

盤面だけ `touch-action: none` と選択/長押し抑止を適用する。説明・結果のスクロール、盤面外のピンチ拡大を妨げない。既存の成功中タップ誤拡大防止を両画面で維持する。

### 3.3 代替操作と説明

通常画面から矢印アイコンと常設左右回転列を撤去する。「輪をなぞって回す」を短く表示し、遊び方には「回したい輪に触れて、輪に沿ってなぞると回せます。」と説明する。正解手順の誘導は追加しない。

スワイプが使えない利用者向けに「補助操作」開閉ボタンをゲーム画面に置き、展開すると「左へ1つ回す」「右へ1つ回す」の文字ボタンを表示する（矢印アイコンなし、各48×48px以上）。展開状態は画面内だけ保持し、ゲーム時計を止めない。VoiceOverでも開いて選択・回転ができる。閉じる際はフォーカスを開閉ボタンへ戻す。通常clickだけで既知問題を完了できる経路を残す。

PCの1/2/3・上下による輪選択、左右キーによる1段階回転、Enter/Spaceによるフォーカス中ボタンの操作を維持する。ここでの「矢印ではなく」は標準の画面操作を指し、アクセシビリティのキーボード経路を廃止しない。入力欄・IME・modifier・repeatを除外する。

## 4. 石板拡大

測定値Dは `.board-host` の正方形のCSS px幅（生成石板と目標を含む300×300領域）。石部分だけの拡大やviewBoxの切り詰めで達成扱いにしない。表示倍率・SVGヒット領域・3Dカメラを一致させる。

| 縦画面（CSS px） | Dの下限 | 比較用の現行CSS上限（実測ではない） |
|---|---:|---:|
| 320×568 | 256 | 204.48（36svh） |
| 375×667 | 320 | 280.14（42svh） |
| 390×844 | 344 | 379.8（45svh、親幅でさらに制限） |
| 393×852 | 347 | 383.4（45svh、親幅でさらに制限） |
| 402×874 | 356 | 384（24rem、親幅でさらに制限） |
| 430×932 | 384 | 384（24rem） |

全6縦画面で同一ブラウザー・同一文字倍率・同一safe area条件の基準版実測D以上、320×568と375×667は基準版実測比10%以上拡大する。下限達成だけで現行より小さくしてはならない。幅優先の配置と余白整理で実現し、足りなければ仕様未達として報告する。

通常文字・補助操作閉で、番号/難度/時間/目標数/盤面/輪選択/手数/補助操作/遊び方/中断（練習ではやり直し）を指定縦画面の可視領域へ収める。safe areaを除いた領域で欠け・重なり・横スクロール0。文字200%と補助操作展開時は必要な縦スクロールを許可し、盤面以外の操作到達を優先する。文字を縮小して目標を満たさない。

844×390、852×393、1280×720、1440×900は現行版以上のDを原則とし、全目標・48px操作・可読性を優先する。拡大不足や制約は実測値で記録する。盤面矩形は選択/回転/点灯/成功中に1 CSS pxを超えて移動しない。リサイズ時は再配置を許可し、進行中スワイプだけを中止する。

## 5. SE追加カタログ

既存の `rotate/select/light/success/start/error` を保持。新規名は次の12個で、同じ名前の音高ランダム変化は種類数に含めない。合成パラメーターは初期実装値。全てattack 8ms、末尾gain 0.0001、peak gain 0.05以下。サイン/三角波のみで新規音を作る。

|---|---|---|---|
| SE01 | rotate_inner_l | 内輪の左1段階受理 | triangle / 180 / 50 / 0.025 |
| SE02 | rotate_inner_r | 内輪の右1段階受理 | triangle / 220 / 50 / 0.025 |

| SE07 | swipe_release | 8px以上動かした有効ジェスチャーを未回転で指離し | sine / 240 / 35 / 0.015 |

一つの受理回転では `success > light（新しく点灯した必須目標あり）> target_lost > 輪別回転音` の1音を選ぶ。点灯と消灯が同時ならlightを優先。成功時に選択音・回転音・点灯音を重ねない。既存rotateは互換用フォールバックとし通常入力では輪別音を使う。1問確認も同じ選択規則を使うが、カウントダウン/次問/完走/練習やり直し音は該当する5問モードだけ。

回転系・select・swipe_releaseは同種の60ms以内の連続再生を間引き、予約蓄積しない。ゲーム入力は間引かない。ページ全体で同時発音4以下、1音のgain 0.05以下（合成最大0.2）、上限時は最古の低優先音を終了して新音を鳴らす。成功音を低優先音で追い出さない。既存音も上限に含める。

初回の信頼できる操作でAudioContextを解除し、解除の遅延で120msより古くなった音は破棄する。OFF、hidden/pagehide、問題世代変更、終了、disposeで古い予約・発音を停止。再開失敗やAudioContext非対応は無音で続行し、未処理Promise拒否0。音の失敗は判定・時計・保存を変更しない。ポインターのシステムキャンセルは無音。実機音量の適切さはiPhoneで別に試聴する。

## 6. 追加視覚演出50個

### 6.1 数え方・共通制約

「1個」は一意なFX ID、発火条件、見た目、終了条件を持つ1演出。色違い/乱数/左右反転/粒子の個数/SEは追加個数に数えない。既存の両側紙吹雪は `legacy-confetti` として別枠で維持し、表の50件に含めない。50件を同時に再生せず、自然なイベントへ対応させる。採用90問とUIフローのどの操作で各IDへ到達できるかを実装時に記録する。

全演出は補助情報であり、到達していない目標への発光、遮断の先への光、解の示唆、画面揺れ、カメラ移動、全画面点滅を行わない。装飾は `pointer-events: none` / `aria-hidden=true`。意味ある状態ラベル・成功通知は従来のDOMで1回だけ伝える。

動きを減らす設定ではアニメーション・粒子を生成せず、既存の選択枠/状態文/成功文などの静的表示をそのまま利用する。設定を途中でONにした時も動的ノードを即時撤去する。成功後の1,500msや入力受付は設定で変わらない。

### 6.2 同時発生・終了・性能

イベント単位で `eventId/runGeneration/questionGeneration` を付け、同じイベントの再描画では再発火しない。光の差分は受理時の必須目標maskとbefore/afterのsnapshotから作り、後の可変stateを参照しない。選択/接点/軌跡/残角度/正常終了とキャンセル、問題番号/初問、画面種別、モーダルからplayingへの復帰をイベントで区別する。具体的な型と描画アンカーは計画T4/T5を正本とする。

演出の選択と開始順を以下で固定する。期限切れの候補の持越しはしない。

成功の400/600/1,200ms予約は成功イベントに属する装飾専用予約とし、run/question世代を照合する。実行遅延で本来の終了時刻を過ぎたものは表示しない。hidden/pagehide/画面変更で全予約を消し、復帰時に追いかけない。進行用1,500ms timerとは分離する。1問確認は5問の時間割のうち各問共通部分のみを使い、FX29/38/39/40は発火しない。

同時表示する追加FXは最大8件、粒子は既存紙吹雪を含め64個、追加装飾DOMは120ノード以下。各FXは追加DOM最大8ノード・粒子最大3個、既存紙吹雪は現行28粒を維持するため、8FX＋紙吹雪でも粒子52以下となる。120ノードには常設の装飾host・紙吹雪コンテナも含めて測る。新たな常時requestAnimationFrameループを作らず、入力のたびに光路をフレーム計算し直さない。FXが失敗しても進行を継続する。

FX21は旧ホームのボタンに描かず、`renderRun`後の新しいカウント欄に描く。DOM設置直後にrun-startを一度送出するが、3秒カウントダウン・時計を演出待ちにしない。結果への入場時はFX41〜43、保存確認後は別のbest-confirmedイベントでFX44を出す。`saveBest().ok`だけをベスト更新と判定しない。保存前に今回より良い/同点記録がないこと、保存成功、保存後readBestのrunId一致を確認する。同点は章を出さず、保存・読込の失敗/不明、練習、異常時計、上限超過も出さない。別タブの良記録を保存後照合で検知した時も出さない（全タブでの原子的順位保証は行わない）。

playing中の盤面装飾は次の受理回転前に破棄し、古い光路の残像を残さない。終了・画面遷移・hidden/pagehide・disposeでtimer/animation/listener/装飾を解放する。背面から戻った際に演出を追いかけ再生しない。成功演出の終了イベントを次問進行の条件にしない。

Q03の5問×20回、THREE系の資源・描画一致を維持して検査する。実機60fpsは目標であって測定前に保証しない。フレーム時間p50/p95/max、入力→確定表示の遅延、JS転送サイズを同一環境の基準版と比較する。持続的なlistener/timer/GPU資源増加0、操作不能0を必須とし、旧性能目標の未達は既存の未達と分けて報告する。
