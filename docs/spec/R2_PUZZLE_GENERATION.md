# R2 問題生成と採用記録

更新: 2026-09-21 / 設定版: `r2-config-v1` / seed: `20260919`

この記録は、常時発光・回転のみの `stone-rings-v2` で問題を作り直した手順と、生成前に保存した数値を正本として残す。公開問題は `content/puzzles-v2.json` の `Puzzle[]` だけにし、探索結果・代表解・採否理由は `reports/r2/` に分離する。

## 生成前に固定した値

計画書 v2.0 §4.2 の初期検証案を変更せず、`src/puzzles/config.ts` に保存した。

| 条件 | 初級 | 中級 | 上級 |
|---|---:|---:|---:|
| 最短手数 | 4〜6 | 7〜10 | 11〜15 |
| 必須受光紋 | 2〜3 | 3〜4 | 4〜5 |
| 発光紋 | 3〜4 | 4〜5 | 5〜6 |
| 遮断石 | 2〜3 | 3〜4 | 4〜5 |
| 最短解で操作する最小環数 | 2以上 | 3 | 3 |
| 最短距離の完成配置数 | 4以下 | 3以下 | 2以下 |

成立条件として、初期完成を除外し、解があり、1環4部品以下・合計12部品以下、3環すべてが光路へ影響することも検査した。候補数は各難度300問、採用数は各30問で固定した。校正値は `C = 100 × shortestMoves + 40 × minOperatedRingCount + 25 × max(0, 4 - shortestGoalStateCount)` とし、券生成前に採用90問から基準値と±10%の範囲を保存した。

設定版を上げる数値変更は今回なかった。候補数不足や範囲外を条件緩和で埋めず、難度ごとの最大15,000試行という有限の探索予算と却下理由を成果物へ残す。

## 探索契約

`src/puzzles/solver.ts` の `analyzePuzzle` は、状態を内・中・外の回転量 `[0..11]` とし、操作順 `[l0,r0,l1,r1,l2,r2]` の6操作で幅優先探索する。探索範囲は1,728状態で、同じ最短距離にある異なる完成状態と、完成状態までの操作列を分けて数える。操作列数は十進文字列で返すため、数値の丸めがない。

解析の `minOperatedRingCount` は全最短解の環集合を比較して求め、`requiredRingIndexes` は全最短解の共通部分から求める。解なしは `shortestMoves=null`、`shortestPathCount="0"`、`truncated=false`（全状態を検査済み）とする。高速bitmask計算の全状態結果は `enumerateFastLitMasks` で独立検査へ渡せる。

## 候補、重複、旧90問

生成候補は固定seedから作り、成功配置の実際の点灯集合から必須受光紋を選ぶ。各環の部品パターンを環ごとの循環シフトで正規化し、受光紋の全体回転・共通反転も含めて、回転・反転・難度横断・初期角だけ違う問題を除外した。初期角を部品スロットへ織り込んだ場合も、初期の物理配置キーで近似重複を検査する。

旧 `prototype` の90問は読み取り専用で常時発光へ変換し、同じsolverと難度条件で再解析した。条件に合った旧easy 18問は候補として優先再利用し、残りを新規生成で補った。旧normal・hardを含む条件外の問題は、旧ID、変換後解析、再利用・調整・差替え・却下理由、対応する新IDを `reports/r2/migration.json` に1件ずつ記録した。prototype側のファイルは変更していない。

## 成果物

- `content/puzzles-v2.json`: 採用90問（初級30・中級30・上級30）の公開用 `Puzzle[]`。
- `reports/r2/analyses.json`: `{puzzleId, ...PuzzleAnalysis}[]`。
- `reports/r2/config.json`: 生成前に保存した設定と数値案。
- `reports/r2/generation.json`: seed、候補検査数、採用数、有限探索結果。
- `reports/r2/candidates.json`: 候補ごとの解析と却下理由。
- `reports/r2/migration.json`: 旧IDから新IDへの変換と理由。
- `reports/r2/near-duplicates.json`: 近似重複の関係、保持・除外判断。
- `reports/r2/ticket-calibration.json`: 900組生成前に固定した基準と±10%範囲。

`puzzles:validate`、`tickets:validate`、`puzzles:test --runs 100000` で形式、難度、checksum、固定seed再生成、独立光路照合、900組、10万回抽選と5σ検査を実行する。人による試遊とiPhone実機検査はR2の自動検査に含めず、未実施として扱う。
