# sekibanmawashi

石の環を回し、発光紋から外周の必要な受光紋へ光を届けるブラウザ向けパズルです。カメレオンJPの実験場のゲームとして扱うため、正式版の整備を進めます。

**最新の計画は文書版2.0です。発光紋は常時発光とし、回転だけで解きます。R1の判定、R2の90問・900組、R3の盤面・入力に続き、R4の5問進行・時計・端末保存・結果と共有を実装しています。検査状況は[R4検査記録](docs/reviews/R4_VERIFICATION.md)で管理します。**

## 現在の状態

`src/`と`content/`が正式版です。通常のURLでは名前入力のホームが開き、チャレンジまたは練習で5問を解けます。記録は端末内で扱い、保存に失敗しても結果と共有を利用できます。R4は68単体テスト・54画面検査と独立レビューを完了しました。実機受入・一般公開は未完了です。

`prototype/`には旧規則の比較用試作があります。旧90問と画面が存在することと、正式版の受入が完了していることは別です。ランキング連携は今回の対象外です。本番公開と実験場側の変更は、受入と公開指示の後に行います。

## 検査

Nodeの版は `.nvmrc` に固定しています。リポジトリ直下で次を実行します。

```sh
npm ci
npm run typecheck
npm run lint
npm run licenses:check
npm test
npm run puzzles:test
npm run build
npm run performance:r5
npm run test:e2e:install
npm run test:e2e
```

`puzzles:test`は保存された90問・900組、独立計算、再生成の一致、10万回の抽選を検査します。生成と検証のコマンドは分け、検証で壊れた公開データを上書きしません。`test:e2e`はR3の盤面検査とR4の5問のアプリ検査をChromium/WebKitで実行します。初回は対応ブラウザと実行に必要なライブラリの導入が必要です。iPhone実機確認とは区別します。GitHubの自動検査から本番公開は行いません。

実装範囲は[R3盤面と入力](docs/spec/R3_BOARD_INPUT.md)と[R4進行・時計・保存](docs/spec/R4_RUN_TIMER_STORAGE.md)、検査結果は各段階の検査記録を参照してください。ローカルでは `npm run dev` でホームを開けます。`?puzzleId=採用済みの問題ID` は引き続き1問の盤面確認用です。不明なIDは読込エラーとし、別問題へ差し替えません。この確認用指定はチャレンジ抽選や記録には使いません。

問題・問題庫・券を作り直す手順と形式は[R2問題生成](docs/spec/R2_PUZZLE_GENERATION.md)、[R2問題庫・抽選券](docs/spec/R2_POOL_TICKETS.md)を参照してください。[検査レポート](reports/r2/report.html)に90問の盤面と採否・統計をまとめ、[R2検査記録](docs/reviews/R2_VERIFICATION.md)に実行結果と未確認を記録します。

## 変更後に固定する内容

12方向・3本の環で、選択と左右の回転だけを操作します。選択は0手、回転は1手です。初級30問・中級30問・上級30問から、初級2問・中級2問・上級1問を出し、5問の実プレイ時間を合計します。日替わりにはしません。

発光紋と遮断石による遮断、光どうしは遮らないこと、余分な光を許可することは維持します。既存90問は新規則で再検査し、条件外の問題だけを調整・差し替えます。

[旧計画v1.2](docs/archive/v1.2/IMPLEMENTATION_PLAN.md)は履歴です。旧6段階や発光切替の条件を現行実装へ混ぜません。正式な公開名、公開用画像、実験場への掲載方法は公開前に確認し、未決定値を推測して登録しません。
